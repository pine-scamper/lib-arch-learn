# 研究范围与问题清单

## 1. 为什么研究这个项目？

希望通过 spdlog 学习：组件职责划分、接口抽象、对象组合、同步/异步执行路径，以及 C++ 库的可扩展 API 设计。

## 2. 本轮研究边界

**研究：** Logger、Sink、Formatter、Registry、异步日志线程池。

**暂不研究：** 与本轮目标无关的平台细节、每一种 Sink 的全部实现、所有宏和兼容层。

## 3. 需要回答的问题

- [ ] Logger 为什么不直接负责文件、控制台等所有输出细节？
- [ ] 一个 Logger 如何持有和调用多个 Sink？
- [ ] Formatter 和 Sink 的职责边界是什么？
- [ ] 新增一种输出目标，需要实现什么接口、改动哪些代码？
- [ ] Registry 解决了什么问题？它引入了什么全局状态或耦合？
- [ ] 异步日志的生产者、队列、消费者分别是什么？
- [ ] 队列满时有哪些策略？不同策略如何影响延迟和日志丢失？
- [ ] Logger、Sink、线程池的所有权和生命周期如何管理？

## 4. 完成本轮研究的判断标准

- [ ] 不看源码，能画出核心组件图。
- [ ] 能从一次 `logger->info(...)` 追踪到具体输出。
- [ ] 能解释同步和异步路径的差异。
- [ ] 能写一个自定义 Sink。
- [ ] 能独立设计一个简化日志库，并解释关键取舍。
