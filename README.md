# lib-arch-learn

目标：通过精读优秀 C/C++ 开源项目，训练模块划分、接口设计、并发模型、资源管理和系统架构能力；最终能够独立设计同类系统。

## 仓库分区

- `libraries/`：上游项目源码，尽量保持原样，并记录版本/commit。
- `studies/`：源码研究资料，包括架构、调用链、设计模式、关键模块和复盘。
- `playground/`：脱离原项目、自己实现的简化系统，用来验证理解。
- `templates/`：新项目研究时复制使用的模板。

## 推荐工作流

1. 固定源码版本：记录 release/tag、commit、编译选项和平台。
2. 先写 `00-scope.md`：明确这次研究的问题和范围，不要试图一次读完整个项目。
3. 画模块图，再追一条端到端调用链。
4. 对每个设计结论记录源码证据：文件、类/函数、调用关系。
5. 记录设计取舍：它解决什么问题、付出什么代价、还有什么替代方案。
6. 在 `05-experiments/` 或 `playground/` 中做最小实验。
7. 在 `06-design-reconstruction/` 中脱离原代码重新设计一个简化版本。
8. 在 `07-synthesis.md` 中总结可迁移的设计原则。

## 研究记录建议格式

每条重要结论尽量遵循：

> 问题/需求 → 设计结论 → 源码证据 → 运行验证 → 设计权衡 → 可迁移原则

不要只写“这里使用了工厂模式”。要解释为什么需要创建抽象、谁负责创建、扩展时改动哪些模块，以及这个方案的代价。

## 新增一个研究项目

复制 `templates/project-study/` 到 `studies/NN-project-name/`，再根据实际项目增删文档。不要为了目录完整而制造空笔记。
